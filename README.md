# DOMO

> 多 Agent 协作工作台 —— 把一群 AI Agent 组织成一个团队，你只做负责人。

DOMO 是一个开源的个人项目。你以一个**工程**（完整产品）为中心，启动若干**项目**（对产品的迭代），每个项目自动拆解为一组**任务**，由一组 BYO 的 Agent 团队完成规划、执行、验收与调度，直到项目结束。
你可以从宏观层面掌握整体进展，也可以深入任意任务查看全过程（含每次调用的输入与输出），还可以随时介入裁决。

## 核心理念

- **三级结构**：工程（完整产品）→ 项目（迭代）→ 任务。工程只承载"产品是什么、在哪儿、用谁、有什么约束"，不承载目标与进度；项目才有目标、里程碑与报告。
- **两类角色**：**规划者**（规划 + 验收）与**执行者**。**一切裁决由人做**——收件箱是唯一裁决入口，选项按待决类型动态呈现。
- **执行 + 验收闭环**：每个任务先由执行者产出计划，规划者审查通过后执行，再由同一规划者验收；结论只有「通过 / 退回」。
- **目标导向验收**：验收者对照任务目标与验收标准判断，不只审执行者提交的内容。机械检查只做两类——**文件存在 / 不存在**、**命令返回码**；其余要求由验收者自行调用工具核查。证据随任务归档。
- **自动调度**：任务按依赖关系（DAG）自动推进，前置完成即启动后继；里程碑是人工确认与调整后续规划的窗口。
- **工作区隔离**：单仓工程在 DOMO 工作区内为每个任务开 git worktree，可并行；多仓工程直接在工程目录操作，每仓一个项目分支，项目与任务串行，切换项目需先暂停并逐仓切分支。
- **随时人工管控**：项目暂停 / 恢复 / 强制暂停 / 取消（归档），或对单个任务给出具体指导、指定 Agent。
- **可审计**：全过程事件溯源；任务的轮次日志、产物、验收证据，以及每次 Agent 调用的提示词与完整输出都可回放。
- **异常可恢复**：失败换人、限流熔断、空闲看门狗判卡死；中断任务按三档恢复（原生会话恢复 → 交接摘要重建 → 人工重建）。
- **BYO 与统一接入**：Agent 由你提供，首个适配器为 OpenCode；不同 Agent 对上层表现为一致的能力、错误语义、恢复与用量。

## 当前状态

产品设计已按新方案重写：[docs/DESIGN.md](docs/DESIGN.md)。
代码正在向该设计收敛——现存实现仍带有旧概念（决策者自动裁决、开工前验收标准协商、多仓串行与仓库级排队等），将随重构逐步移除。

已可运行的部分：

- **规划与确认**：规划者自动拆解项目（含里程碑）；人工确认迭代（带意见重新规划、原子替换）；人工介入探讨通道
- **任务闭环**：计划 → 计划审查 → 执行 → 验收；退回即返工；人工可随时接管验收
- **Agent 池**：角色优先级表；按优先级动态选人并在高优先级 Agent 处排队；失败换人、限流熔断；人类可固定单任务 Agent
- **隔离与合入**：任务工作区（git worktree / 独立子目录）；验收通过后合入项目基线，冲突交人
- **恢复**：三档恢复降级（原生会话恢复 → 交接摘要重建 → 人工重建），进程重启后从最后状态续跑
- **可观测**：事件溯源与审计（倒序/分页/筛选/关联详情）、任务轮次日志、Agent 输出归档、服务端运行日志、项目总结报告

## 快速开始

```bash
# 1. 构建前端
cd web && npm install && npm run build && cd ..

# 2. 构建并启动后端（同时托管前端静态资源）
cd server && cargo run --release
# 打开 http://127.0.0.1:8787
```

数据（SQLite）存放在 `data/domo.db`；服务端运行日志同步写入 `data/domo.log`（可用 `DOMO_LOG` 改路径、`DOMO_LOG_LEVEL` 调级别，默认 info）。

## 技术栈

- 后端：Rust (Axum + Tokio + rusqlite/SQLite)
- 前端：React + Vite + TypeScript
- Agent：BYO，通过适配器接入（OpenCode 以 CLI 独立进程为默认；HTTP 宿主为实验性开关（默认关闭），另有 Mock）
