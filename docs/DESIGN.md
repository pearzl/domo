# DOMO 设计

> 本文件描述**当前设计**（不含历史演进与实施过程）。

## 1. 产品定位

DOMO 是**多 Agent 协作工作台**：你以一个**工程**（完整产品）为中心，启动若干**项目**（对产品的迭代），每个项目自动拆解为一组**任务**，由一组 BYO 的 agent 团队协作完成规划、执行、验收与调度，直到项目结束。

- **本地优先、单用户**：数据与工作区都在本机，不依赖云服务。
- **BYO agent**：agent 由用户提供；首个适配器为 OpenCode，另有 Mock 用于演练与回归。
- **从 coding 起步，面向通用任务**：设计不假设任务一定是写代码，但当前以 coding 场景为主要验证对象。
- **人只做负责人**：规划与验收由 AI 完成，关键节点由人确认或裁决。

## 2. 名词表

| 名词 | 含义 |
|---|---|
| **工程** | 一个完整产品；承载"产品是什么、在哪儿、用谁、有什么约束"，**不承载目标与进度** |
| **项目** | 工程的一次迭代；有目标、里程碑、任务 DAG、验收标准与总结报告；同一工程下可有多个（仅单仓工程可并行） |
| **任务** | 可执行、可验收的最小单元；有计划、证据、日志与产物 |
| **规划者** | 负责规划，**同时是该任务的验收者** |
| **执行者** | 负责执行任务 |
| **团队池** | 「角色 × agent」的优先级表，逐层继承；可在任一层启停与调序 |
| **任务工作区** | 任务的隔离工作目录（单仓为 git worktree；多仓直接在工程目录的项目分支上工作） |
| **收件箱** | 所有需人裁决事项的唯一入口 |
| **证据包** | 验收所需的客观材料：机械检查结果 + 验收结论与依据 |

## 3. 工程、项目与任务

### 3.1 层级职责

| 层级 | 承载 | 不承载 |
|---|---|---|
| 工程 | 名称、简介、**工作区锚点**（单仓/多仓目录/普通目录）、默认团队与策略、知识归属、**防跑偏约束**（技术栈、目录约定、禁改范围） | 目标、路线图、里程碑、进度、报告 |
| 项目 | 目标、里程碑、任务 DAG、验收标准、执行过程、总结报告；**声明本次迭代的基线** | 团队定义（继承自工程） |
| 任务 | 计划、执行、验收、日志、产物、证据、仅本任务有效的人工指导 | 跨任务复用（只通过依赖与产物关联） |

**工程的作用是"防跑偏"**：它不描述"要做什么"（那是项目的目标），而是约束"不能怎么做"与"在哪儿做"——技术栈、目录归属、禁改范围、默认团队与策略。规划与验收时引用这些约束。

### 3.2 复用边界

- **跨工程**：团队配置（可复制）、知识条目（人工显式提升为全局）、工程备份。
- **跨项目**：同一工程内共享团队与池配置、知识、报告归档；不做报告对比。
- **跨任务**：无自动提炼；人工指导只作用于该任务本次/下次尝试。

## 4. 工作区与分支模型

**工作区属于工程**；项目只声明基线；任务在基线上工作。按工程类型分三种工作方式：

| 工程类型 | 工作方式 | 并发 | 隔离 |
|---|---|---|---|
| **单仓（git）** | 在 DOMO 工作区（`~/.domo/workspace/<工程>/`）内，每任务开 **git worktree** | **允许**：多项目并行、同项目多任务并行 | worktree 天然隔离；合入前同步基线 |
| **多仓（git 多仓库目录）** | **不使用 DOMO 工作区，直接在工程目录内操作**；每仓一个项目分支 | **不允许**：同一时刻只有一个项目、一个任务 | 项目分支隔离；切换时逐仓切分支；要求工作区干净 |
| **普通目录（非 git）** | 直接在工程目录（或默认目录）内操作；任务可用子目录 | 允许（无版本控制保护） | 目录级，弱隔离 |

### 4.1 单仓工程

- 项目声明基线（分支/提交）；任务从基线开 worktree，互不干扰、可并行。
- 验收通过 → 先把任务分支同步到项目基线最新，再合入；冲突交人处置。
- 项目完成 → 由人决定是否合回工程主干。

### 4.2 多仓工程（简化模型）

- **项目 = 每仓一个同名迭代分支**（`domo/iter-<项目短标识>`，从各仓主干切出）；项目记录"每仓当前分支"。
- **串行**：同一多仓工程同一时刻只有一个项目、一个任务。
- **切换项目**：① 暂停当前项目 → ② 逐仓检查工作区干净 → ③ 逐仓 checkout 目标项目分支（不存在则按主干创建）→ ④ 恢复目标项目。任一仓不干净则**阻止切换**，列出脏仓库与文件。
- **任务**：串行执行，直接在该项目分支上改动；验收通过后提交一次（便于回溯）。
- **项目完成**：**默认不合回主干**，保留分支；是否合回由人事后决定。

### 4.3 普通目录工程

直接在工程目录工作；任务可用子目录隔离；界面明确提示"无版本控制保护"。

## 5. 项目（迭代）生命周期

```
initializing ──确认规划──> running ──暂停──> pausing ──会话排空──> paused
      │                        │                                      │
      │ 带意见重新规划（原子替换） │ 全部任务终态                          └──恢复──> running
      └───────────────────────> completed ──> archived（只读）
```

- **initializing**：规划者可生成/调整规划；**人工确认（任务拆分、里程碑、目标）后才进入运行**。
- **running**：调度器自动推进（计划 → 审查 → 执行 → 验收）。
- **pausing → paused**：暂停冻结一切新派发；常规暂停等待在途会话跑完当前尝试后自动转「已暂停」；也可「强制暂停」立即终止会话。**人工裁决不受暂停限制**。强制暂停只作用于本项目的会话，不得影响其他工程或其他项目的任务；若受 agent 宿主限制无法避免影响，必须先提示人并由人确认。
- **completed**：全部任务终态，自动产出项目总结报告。
- **archived**：取消即归档，数据、日志、事件全量保留、只读。

**确认迭代**：规划不是一次性的——人可以提修改意见，规划者据此重做整版方案（**原子替换**：新方案生成成功才替换旧方案，失败则旧方案原样保留），直到人确认。多仓工程在确认前需选定项目分支。

## 6. 任务生命周期

```
planned ──依赖就绪──> ready
   │                    │
   │                    ▼
   │             plan_drafting ──计划产出──> plan_review ──通过──> executing
   │                    ▲                        │打回（≥2 轮 → escalated）
   │                    └──── 重拟计划 ◄──────────┘
   │                                                 │执行完成
   │                                                 ▼
   │                                        awaiting_acceptance
   │                                          │通过 → done
   │                                          │退回（≥2 轮 → escalated）
   │                                          └────────────► executing（返工）
   └─ 中断 → recovering（等待恢复续跑）；失败 3 次 → suspended
```

- **计划**：执行者先产出任务计划（步骤、将改动的文件/产物、验证方式、风险），规划者（即验收者）审查通过后才执行。
- **验收结论只有「通过 / 退回」**：退回即返工（重新执行）；不存在"重试验收"。
- **"重试"仅指验收者运行失败**（限流/超时/配置错）后的自动换人重试，不影响验收结论、不占退回次数。
- **中断恢复**：进程重启导致会话中断的任务进入 `recovering`，按三档恢复（原生会话恢复 → 交接重建 → 人工重建）续跑；恢复期间不显示为"执行中"。
- **失败与升级**：执行失败 3 次挂起；计划/验收退回 2 轮升级；均不阻塞无依赖分支。

## 7. 角色与团队

### 7.1 角色

- **规划者**：负责规划，**同时是该任务的验收者**。
- **执行者**：负责执行。
- **人**：一切裁决（收件箱）与关键确认（规划、gate）。
- **同任务执行与验收允许同一实例**：界面仅在"执行者与验收者为同一实例/同一模型"时提醒独立性有限，不作为硬约束。

### 7.2 团队池与继承

- 配置层级：`DOMO 全局 → 工程 → 项目 → 任务`，下层可覆盖上层；未覆盖时继承。
- 每个角色一份**有序列表**：数字越小优先级越高；可启用/禁用；列表恒连续编号。
- **任务默认按优先级动态选人**：**空闲不作为分配依据**，任务在最高优先级 agent 处排队（忙则等待，不降级）。
- **人类可对单任务固定 agent**（例外通道）。
- **队列人工可调**：项目整体优先 + 任务插队，调整立即生效。

### 7.3 选人与排队策略

默认策略为「优先级优先」；选人与排队是**可扩展的策略**（如轮转、负载均衡、亲和性），上层调度不写死具体策略。

### 7.4 统一 Agent 接入

不同 agent（不同 CLI、模型、供应商）对上层表现为**一致行为**：能力声明（会话恢复、并行上限、限流冷却）、错误语义、恢复方式、用量统计。适配器的差异不泄漏到调度与界面。

### 7.5 容错

| 失败类型 | 处置 |
|---|---|
| 限流 / 额度不足 | 该 agent **全局临时熔断**（时长由该 agent 配置或供应商提示决定），期间所有项目跳过该 agent；改派下一优先级 |
| 配置错误（如模型无效） | 熔断较长时间并提示人工修复；改派下一优先级 |
| 供应商抖动 / 网络 | 短期退避 + 改派下一优先级 |
| 卡死 | **空闲看门狗**：不限制总运行时长，持续无输出达到该 agent 的超时阈值即终止进程；改派下一优先级 |
| 换人重试 | **不计入失败预算**；池内候选耗尽才计失败（3 次挂起） |
| 连续失败重试间隔 | 指数退避（5s → 300s 封顶） |

## 8. 规划与确认迭代

- **规划输入**：项目目标、工程防跑偏约束、团队池、工程仓库清单与拓扑（多仓）。
- **规划产出**：任务（标题、描述、依赖、验收标准）+ 里程碑分组。
- **讨论式确认**：
  - 主体是**对话**（人提意见 → 规划者回复并给出新方案），右侧常驻**方案摘要卡**（目标、任务数、里程碑、关键依赖）。
  - 变更以**差异**呈现（新增/修改/删除高亮），可回到上一版。
  - 团队池等配置性内容放在侧栏，不占据规划主视野。
  - 确认后方案**锁定**，作为执行与验收依据；重规划为**原子替换**。
- **结构化要求**：规划输出中，验收标准必须是结构化检查项（见 §9）；格式不合法时要求重试或按错误退回。
- **归档**：每次规划调用的**输入（提示词与上下文）与输出（完整回复）**均归档，供审计回放。

## 9. 验收机制

**目标导向**：验收者必须对照**任务的交付目标与验收标准**判断，不能只审执行者提交的内容——避免"执行者思路错误，验收者跟着错"。

### 9.1 两层判定

| 层 | 内容 | 谁执行 |
|---|---|---|
| **机械检查**（仅两类） | ① 文件存在 / 不存在 ② 命令执行返回码 | 系统自动执行（在任务工作目录内） |
| **语义核查** | 其余所有要求（质量、合理性、目标达成度） | 验收者（规划者）**用自己的工具调用**核查（读文件、跑命令），不预设类型 |

- 机械检查结果进入**证据包**；验收者结论必须**引用机械结果与任务目标**。
- 验收的其余部分不做结构化——交给验收者自行使用工具判断。

### 9.2 结构化产出与校验

- 规划输出中验收标准形如：
  `{"type":"file_exists","path":"..."}`、`{"type":"file_not_exists","path":"..."}`、`{"type":"command","cmd":"...","expect_exit":0}`
- 系统做 schema 校验（字段、类型、必填）；不合法 → 重试或按格式错误退回。
- 确认迭代时以表格呈现检查项，人可直接编辑；**确认即锁定**。

### 9.3 证据与呈现

- **证据包**：机械检查结果 + 验收结论与依据 + 产物路径，随任务归档。
- **验收一屏**：目标 / 验收标准 / 任务计划 / 机械结果 / 验收者结论，一键通过或退回。
- **独立性提醒**：执行与验收同实例/同模型时提示。

### 9.4 命令执行边界

- 命令在任务工作目录中执行（单仓为 worktree，多仓为项目分支目录）。
- **不设白名单**（规划者可自由登记命令），但一律记录审计：谁声明、跑了什么、结果如何。
- 设执行时限与输出上限，避免单条检查拖死验收流程。

## 10. 调度与并发

- **依赖驱动**：任务依赖全部完成才可派发；`planned → ready` 后进入计划阶段。
- **里程碑 gate**：里程碑内任务全部完成 → 停下等人工确认，**只挂该里程碑的下游分支**；gate 是重规划的窗口。
- **并发规则**：
  - 单仓工程：同项目多任务并行（worktree）；多项目也可并行。
  - 多仓工程：项目与任务均串行（见 §4.2）。
  - 普通目录：允许并行，但无版本控制保护。
- **选人与排队**：见 §7.2 / §7.3。
- **周期扫描**：调度器周期性推进各项目的可派发任务，并处理中断恢复、退避重试、熔断跳过。

## 11. 人机协作

- **收件箱是唯一裁决入口**：所有需要人判断的事项都进入这里。
- **选项按类型动态呈现**：每个条目携带类型（卡死、退回升级、豁免、里程碑 gate、规划变更、新增 agent、项目切换受阻等），界面**只渲染该类型适用的动作**；新增类型只需扩展该类型的选项集。
  - 例：卡死/失败挂起 → 恢复重派 / 更换执行者 / 更换验收者 / 放宽标准 / 放弃任务
  - 例：里程碑 gate → 确认通过 / 退回并进入重规划窗口
- **人工介入**：与规划者对话探讨方案，保留上下文记忆。
- **任务指导**：针对单个任务给出指导，作用于该任务本次或下次尝试。
- **人工验收/退回**：随时可接管验收。
- **不做**"该做什么"的 AI 建议提示（默认不触发）。

## 12. 可观测与审计

- **事件溯源**：任务、项目、里程碑、agent、规划与人工操作的全过程事件。
- **执行日志按轮次**：同一任务的每次尝试独立成段，轮次间最新在前、轮次内时序。
- **输入与输出归档**：每次 agent 调用的**提示词与上下文**（含注入的知识条目）与**完整输出**均归档，可回放。
- **审计视图**：倒序、分页、按类型/时间/项目筛选；条目可展开关联详情（任务快照、会话、日志、错误与处置）。
- **实时刷新**：**所有视图在后台保持最新**，切回即最新；仅刷新本地界面，不向外部推送。
- **服务端运行日志**：记录 API 错误、状态流转、agent 运行与失败原因，便于事后排障。

## 13. 界面信息架构

### 13.1 设计原则

1. **以事情为中心**：界面围绕"目标—方案—证据—结论"组织，配置项退居侧栏。
2. **三层导航**：工程 → 项目 → 任务，任何页面都能明确"我在哪个工程/项目/任务"。
3. **状态永远可见**：每个任务/项目都能一眼看出"在做什么、卡在哪、等什么"。
4. **人在关键处介入**：需要人时集中到收件箱，不让用户在页面间寻找待办。
5. **一切可回溯**：任意任务可回放到事件、日志、输入输出。

### 13.2 全局框架

- **左侧导航**：工程列表（当前工程高亮）→ 该工程的固定入口：总览 / 项目 / 团队 / 收件箱 / 审计 / 知识库 / 设置。
- **顶部栏**：面包屑（工程 → 项目 → 任务）、全局搜索（任务/事件/知识）、**通知中心**（前端通知）、全局状态（是否有待裁决）。
- **主区**：当前视图内容；右侧可滑出**详情抽屉**（任务/事件/条目），不打断主上下文。
- **全局组件**：状态徽标（颜色语义统一）、空态、错误态、分页（每页 15）。

### 13.3 视图与职责

| 视图 | 内容 | 关键交互 |
|---|---|---|
| **工程总览** | 工程基本信息（简介、工作区、约束、默认团队）、项目列表（状态、进度、待裁决数）、最近活动 | 新建项目；进入项目；编辑工程信息与约束 |
| **项目视图** | 项目目标、里程碑与进度、任务 DAG（默认）/ 看板、需人事项、报告 | 规划台（初始化态）；确认规划；暂停/恢复/强制暂停；归档；进入任务 |
| **规划台** | 对话（人 ↔ 规划者）+ 方案摘要卡 + 差异列表 | 提意见 → 重新规划；采纳并确认；回到上一版；团队/池配置在侧栏 |
| **任务详情（抽屉）** | 目标与验收标准、任务计划、执行过程（时长 + 转圈 + 日志滚动）、证据与结论、日志按轮次、事件时间线 | 人工指导；人工验收/退回；固定/更换 agent；查看输入输出归档 |
| **团队** | agent 列表（角色、能力、负载、队列、熔断状态）、池配置（含继承来源标识） | 启停、调优先级、复制团队配置；**队列调序（项目整体 + 任务插队）** |
| **收件箱** | 待裁决（按类型分组的卡片：上下文 + 证据 + 动态选项）、已处理（分页） | 一键裁决；查看关联任务/事件 |
| **审计** | 事件流（倒序、筛选、分页）、关联详情抽屉 | 按类型/时间/项目过滤；查看关联任务/输入输出 |
| **知识库** | 条目列表与编辑、来源追溯、注入可见性 | 新建/编辑/提升为全局；查看某任务注入了哪些条目 |
| **设置** | 全局默认团队与策略、预算上限、通知开关、工作区根与日志位置 | 配置继承的顶层默认值 |

### 13.4 关键交互流程

1. **新建项目 → 规划 → 确认**：工程总览新建项目（填目标）→ 进入规划台（与规划者对话、提意见）→ 看差异、确认方案 → 项目进入运行。
2. **过程中需要人**：顶部出现待裁决提示 → 收件箱按类型展示（含上下文/证据）→ 选择该类型允许的动作 → 立即生效并回到原上下文。
3. **任务执行中**：任务卡显示"执行中 + 已运行时长"；打开详情可见转圈动画与滚动日志；完成后展示证据与验收结论。
4. **多仓项目切换**：切换项目时若当前项目在运行，先提示"需暂停"；暂停后逐仓检查干净并切分支，失败时列出脏文件并阻止切换。

## 14. 数据模型（要点）

- **工程**：id、名称、简介、工作区类型与锚点（单仓仓库 / 多仓目录 / 普通目录）、默认团队与策略、防跑偏约束、知识归属、创建时间。
- **项目**：id、所属工程、目标、基线（单仓分支/提交；多仓每仓分支）、状态、里程碑、总结报告。
- **任务**：id、所属项目、标题、描述、依赖、验收检查项、状态、尝试/失败/退回计数、计划、证据、产物、当前 agent、是否人工固定。
- **里程碑**：名称、目标、成员任务、状态（进行中/待确认/通过/退回）。
- **Agent**：名称、适配器、角色、能力（恢复/并行/冷却）、模型与超时、状态（空闲/忙碌/已删除）、占用任务。
- **事件与归档**：全生命周期事件（append-only）；agent 输入/输出归档；任务轮次日志。
- **收件箱条目**：类型、上下文（任务/项目/证据）、状态与裁决记录。

## 15. 未来功能

- **成本与用量**：按 agent/任务/项目/工程 汇总 token、时长、费用；预算上限触顶自动暂停并提示。
- **通知**：前端通知中心先行（待裁决、项目完成、卡死、预算触顶）；外部渠道（桌面/邮件/Webhook）后续开启。
- **审计回放与导出**：任务全过程一键回放；事件族结构化详情；导出可分享报告。
- **备份与恢复**：工程快照（数据 + 工作区）与一键恢复；可迁移机器。
- **项目级钩子**：合入前/完成后的自定义动作（跑测试、发通知、更新文档）。
- **非编程场景与部署体验**：资源上传、产物在线预览；WSL 与本机部署优化（路径与大小写、文件监听、端口占用、CRLF、进程信号）。
- **知识沉淀**：仅人工显式条目（不自动提炼）；注入不设上限，界面提示本次注入了哪些条目。
- **多语言与主题**。

## 16. 现行关键决策

| # | 决策 |
|---|---|
| 1 | 三级结构：工程（产品）→ 项目（迭代）→ 任务；工程只承载基本信息与约束，无目标/进度/报告 |
| 2 | 工作区归属工程；项目只声明基线；单仓用 DOMO 工作区 + 任务 worktree |
| 3 | 多仓工程简化：**直接在工程目录操作**，项目与任务串行；每仓一个项目分支；切换项目需暂停 + 工作区干净 + 逐仓切分支；项目完成默认不合回主干 |
| 4 | 角色简化为规划者（规划 + 验收）与执行者；**一切裁决由人**；不做决策者 agent |
| 5 | 同任务执行与验收允许同一实例，仅界面提醒独立性受限 |
| 6 | 团队池逐层继承（全局→工程→项目→任务）；启停与优先级保留；选人/排队策略可扩展；队列人工可调 |
| 7 | 任务不在规划时绑定 agent；默认按优先级动态选人并在高优先级 agent 处排队（空闲不作为依据）；人类可对单任务固定 |
| 8 | 确认迭代为讨论式，重规划原子替换（成功才替换），确认后锁定 |
| 9 | 验收目标导向；机械检查仅两类（文件存在/不存在、命令返回码）；其余由验收者用工具核查；证据包 + 验收一屏 + 独立性提醒 |
| 10 | 验收结论只有通过/退回；"重试"仅指验收者运行失败后的换人重试 |
| 11 | 失败容错：错误分类 + 限流/配置错全局熔断 + 改派下一优先级（不计失败预算）；卡死按静默时长判定 |
| 12 | 收件箱选项按待决类型动态呈现；不做 AI 建议提示 |
| 13 | 可观测：事件溯源 + 轮次日志 + **agent 输入与输出归档**；所有视图后台实时刷新（仅本地） |
| 14 | 进度呈现：已运行时长 + 转圈 + 日志滚动；"为什么还没开始"明确原因；不做预计等待 |
| 15 | 不做跨项目报告对比；知识沉淀仅人工条目、不设注入上限但提示注入内容 |
