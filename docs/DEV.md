# DOMO 开发契约

> 本文只约定**仓库整体层面**的规范：目录用途、可入库内容、测试与验收、变更要求。
> 具体模块的实现约束写在对应文件的头部注释里（Rust `//!`、前端文件头注释）——改一个模块前，先读它自己的契约。

## 1. 目录结构与使用规范

| 目录 / 文件 | 用途 | 规范 |
|---|---|---|
| `server/` | Rust 后端（`src/` 与 Cargo 配置） | `target/`、`data/` 不入库；模块约束写在各 `*.rs` 文件头 |
| `web/` | React 前端（`src/` 与构建配置） | `node_modules/`、`dist/` 不入库；跨视图状态集中在 `src/store.tsx` |
| `tests/` | 冒烟脚本（`smoke_*.sh`） | **只放可执行脚本**；用例说明写脚本头部注释；不建子目录、不放运行产物 |
| `docs/` | **长期维护**的文档 | 只允许 `DESIGN.md`、`ARCH.md`、`DEV.md`（需要时加 `API.md`） |
| `data/` | 运行时数据：SQLite、日志、归档、冒烟产物、一次性验收快照 | 全部不入库，可随时删除 |
| 根目录 | `README.md`、`LICENSE`、`.gitignore`、工程配置 | 不新增临时文件、笔记、一次性脚本 |

**docs 目录的边界（重点）**

- `DESIGN.md` 是唯一的产品设计文档；`ARCH.md` 是唯一的技术架构文档；`DEV.md` 是唯一的仓库级开发规范。三者都不放过程记录。
- **禁止**在 `docs/` 新建测试用例说明、验收标准说明、冒烟报告、阶段总结、截图、过程记录。这些内容：
  - 用例与验收标准 → 写进 `tests/smoke_*.sh` 的头部注释；
  - 运行结果、日志、快照 → 放 `data/`（已忽略）或 `${TMPDIR:-/tmp}`；
  - 模块级约定 → 写进对应源码文件头。
- 需要新增一篇长期文档（例如 API 契约）时，先确认它会被长期维护，再在本文的目录表中登记；否则不建。

**通用规则**

- 新建目录前，先确认现有目录能否承载；**不允许"随手建一个目录放文件"**。确需新增目录，必须在本文登记用途。
- 一次性产物（临时脚本、备份、截图、导出、实验代码）一律进 `data/` 或 `/tmp`，不留在源码树里。

## 2. 可入库内容约束

**可以入库**

- 源代码与测试代码（Rust `#[test]`、前端源码）。
- 构建与依赖配置、锁文件：`Cargo.toml` / `Cargo.lock`、`package.json` / `package-lock.json`、`tsconfig`、`vite` 配置。
- 长期文档：`README.md`、`docs/DESIGN.md`、`docs/DEV.md`。
- 冒烟脚本：`tests/smoke_*.sh`。

**不得入库**

| 类别 | 例子 |
|---|---|
| 构建产物与依赖 | `server/target/`、`web/dist/`、`web/node_modules/` |
| 运行时数据 | `data/`、`server/data/`、`*.db` / `*.db-wal` / `*.db-shm`、`*.log`、`*.out` |
| 工作区与隔离目录 | `~/.domo/workspace/`、任何 git worktree 目录 |
| 归档与一次性产物 | 冒烟存档、验收快照、报告导出、日志包、截图、视频、压缩包 |
| 凭据与个人环境 | token、API key、私钥、含本机绝对路径的配置；需要说明时用占位符或环境变量 |
| 编辑器 / 系统垃圾 | `.DS_Store`、`Thumbs.db`、`.idea/`、`.vscode/`、`*.swp`、`*~` |
| 大文件 / 二进制 | 超过约 1MB 的文件需在提交信息中说明理由，否则不入库 |

**执行要求**

- 提交前先看 `git status`：每个改动都能解释来源，不夹带无关文件；新文件先确认归属目录。
- 不通过修改 `.gitignore`、`git add -f` 等方式绕过上述约束；确需例外时必须在提交信息里写明。
- 仓库保持轻量（当前为源码级，约 5MB）；任何改动都不应让它显著膨胀。

## 3. 测试与验收标准

改动的最低验证门槛：

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test                 # 在 server/ 下
cd web && npm run build    # tsc + vite，类型错误即失败
```

- 冒烟脚本放 `tests/smoke_*.sh`，**默认使用 mock agent**，不依赖真实模型与外网；真实模型用例通过环境变量传模型（如 `DOMO_M3_MODEL`、`DOMO_RT_MODEL`），**不把模型名写死在脚本里**。
- 临时目录统一用 `${TMPDIR:-/tmp}`；端口通过 `DOMO_*_PORT` 覆盖；脚本退出码 `0` = 全部通过，结束必须清理自己启动的进程与临时文件。
- **修缺陷必须带回归用例**：Rust 单测（纯逻辑 / 解析 / 迁移）或冒烟断言（流程 / 接口 / 事件），至少其一。
- 涉及并发、锁、调度、恢复的改动，必须验证错误路径：进程被杀、agent 超时、限流熔断、数据库锁竞争。
- 验收以"能实际使用"为准：改完后服务要能启动、视图要能刷出数据，不以"编译通过"作为完成标准。

## 4. 变更要求

1. **设计先行**：行为有变化先改 `docs/DESIGN.md`，技术实现有变化先改 `docs/ARCH.md`，并同步更新 `README.md`（能力描述与文档索引）。三者与实际行为不一致，视为未完成。
2. **一次提交只做一件事**：提交信息写清"改了什么 / 为什么"；涉及数据迁移或行为变更必须注明影响面。
3. **数据不可破坏**：任何删除字段/表的迁移都要先提供回填或兼容读取方案；归档与事件不允许清理。
4. **本轮不推送远端**：提交只留在本地，待重构告一段落后再统一处理。

## 5. 合并要求（rebase 压缩）

- 长期分支只有 `main`；所有改动在短生命周期的特性分支或本地分支上完成，**不在 `main` 上直接开发**。
- 合并进 `main` 一律 **先 rebase、再压缩为单个提交**：`git rebase main` 解决冲突 → `git merge --squash`（或 `git rebase -i` 压缩）→ 一个提交落入 `main`。
- `main` 必须保持**线性历史**：禁止 merge commit（`--no-ff`）、禁止交叉合并、禁止把多个不相关改动塞进同一次合并。
- 压缩后的提交信息：首行（≤72 字）写"做了什么"；正文写"为什么 / 影响面 / 数据迁移与回滚方式"。一个提交只对应一件事。
- 冲突只能在特性分支上（rebase 过程中）解决，**不得在 `main` 上解决冲突**。
- 禁止对 `main` 强推；个人特性分支需要强推时只能用 `--force-with-lease`，且仅限未共享的分支。
- 合并前必须通过第 3 节的验证门槛；合并后再本地启动一次，确认服务可用。
- 本轮暂不推送；恢复推送前，先把本地领先的提交按本规范整理为线性、可读的历史。
