# DOMO 技术架构

> 本文描述**技术架构**：进程与数据怎么摆、一次任务怎么走、故障怎么兜、扩展点在哪。
> 产品行为见 [DESIGN.md](DESIGN.md)；仓库规范见 [DEV.md](DEV.md)。

## 1. 目标与取舍

本地优先、单用户、单机运行；**没有多用户需求**，不做多租户、不做多机集群。架构按"长期常驻的本机服务"设计。

| 目标 | 具体含义 | 可验证指标 |
|---|---|---|
| **高可靠** | 不丢结论、不因单点阻塞整体、进程被杀后可续跑 | `kill -9` 后重启：无重复派发、无重复收件箱条目、任务可继续；连续 24h 无内存与句柄泄漏；故障恢复 < 2s |
| **高性能** | 几十个任务并行时界面与接口仍流畅 | 本机接口 p95 < 50ms；界面事件延迟 < 200ms；启动 < 1.5s；默认 8 个并行会话（可配 32）；10 万条事件翻页 < 100ms |
| **高扩展** | 换 agent、加检查类型、加通知渠道不动核心 | 新接入只需实现对应接口；新增检查类型只需注册；升级只增不改，旧数据可读 |

明确不做：分布式、集群、多用户、跨机同步。

## 2. 术语

| 术语 | 含义 |
|---|---|
| **工程 / 项目 / 任务** | 产品层级，见 DESIGN §3 |
| **会话** | 一次 agent 调用。它有自己的上下文与生命周期，可被单独取消 |
| **执行宿主** | 真正跑会话的进程（如 `opencode serve` 起的 server）。一个宿主可承载多个会话，也可以只服务一个会话 |
| **隔离域** | 允许共用同一个执行宿主的范围。默认按**工程**划分：不同工程不共用宿主 |
| **一次尝试** | 调度器为某任务派发的一次完整执行：准备 → 调用 agent → 收集输出 → 回报结论。一次尝试对应任务的一个 `attempt`。它不是一个线程池，也不是常驻进程；尝试结束后只有事件、日志与产物留下 |
| **任务工作区** | 任务改代码的目录（单仓为 git worktree；多仓直接在工程目录的项目分支上） |
| **事件** | 只追加、不修改的事实记录，审计与恢复的依据 |
| **收件箱** | 所有需要人裁决的事项的唯一入口 |

## 3. 物理视图：本机上到底有什么

```
浏览器
  │  HTTP / SSE
  ▼
domo-server（单进程，常驻）
  ├─ 接口（REST + SSE）
  ├─ 调度器（唯一的推进者）
  ├─ 进程管理（起停宿主、取消会话）
  ├─ 合入队列（按工程串行）
  └─ SQLite  data/domo.db（单写多读）

  ↓ 起停 / 取消（宿主只由 domo-server 管理，不反向写库）

执行宿主 × N（每个工作区一个：单仓=任务 worktree，多仓=工程目录）
opencode serve（cwd = 任务工作区）
  ├─ 会话：任务 1 执行
  └─ 会话：任务 1 验收（同一工作区可多会话）

磁盘
  ~/.domo/workspace/<工程>/        单仓工程的任务工作区
  <工程目录>                        多仓工程（直接在该目录的项目分支上工作）
```

读法：**从上到下是启动与取消的方向，从左到右是并列关系**；宿主之间互不通信，只与 DOMO 交互；数据库只由 domo-server 写入。

三条数据路径，没有别的：

| 路径 | 走向 |
|---|---|
| **状态写入** | 调度器 → SQLite（事务：状态 + 事件 + 收件箱）→ 提交后广播 |
| **执行输出** | 宿主 → 会话输出流 → 日志缓冲/批量落库 → 实时推给界面 |
| **界面刷新** | 浏览器订阅 SSE，按事件 id 续传；查询走只读连接 |

组件职责与边界：

| 组件 | 职责 | 不做什么 |
|---|---|---|
| 接口层 | 校验、命令入队、查询、SSE | 不改状态、不跑 git、不起进程 |
| 调度器 | 推进状态、派发、失败处置、恢复 | 不做长时间 IO，不解析输出 |
| 进程管理 | 起停宿主、取消会话、回收残留 | 不判断业务结论 |
| 合入队列 | 按工程串行合入、冲突上报 | 不排队派发 |
| 执行宿主 | 跑会话、产出事件与输出 | 不写 DOMO 数据库 |

## 4. 两个场景走查

### 4.1 一个任务从派发到验收

1. 依赖就绪 → 调度器用**条件更新**把任务改成 `plan_drafting`，记下 agent 与尝试号。
2. 进程管理确认该**任务工作区**有可用宿主；没有就起一个（`opencode serve`，cwd = 该工作区，独立端口）。
3. 宿主内创建会话，发送提示词；输出按事件流回传，边写日志边推送界面。
4. 会话结束：结论行与输出归档 → 调度器写入结果（计划通过/退回、验收通过/退回）。
5. 通过 → 入合入队列；冲突 → 收件箱；通过且合入成功 → 事件落库并广播，界面即时更新。
6. 退回 → 重新派发一次尝试（计数 +1）；连续失败或轮次超限 → 收件箱。

### 4.2 用户强制暂停项目 A

1. 界面发"强制暂停"命令 → 调度器把项目改为 `pausing`，停止新派发。
2. 调度器列出项目 A 的**在途会话**，逐个请求取消。
3. 宿主支持会话级取消（HTTP 接口）：只中止这些会话。宿主与该任务工作区绑定，其他任务各有自己的宿主，不受影响。
4. 宿主不支持会话级取消，但该宿主只服务项目 A：终止整个进程组（TERM → 3s → KILL），再销毁宿主。
5. 宿主不支持会话级取消：因为宿主只服务该任务工作区，终止进程组不会波及其他任务；仍记录被中止的会话并进入待恢复。
6. 任何被连带中断的会话：事件记录 `interrupted_by = pause:<project>`，任务进入待恢复，并按产品要求提示"本次暂停影响了其他项目"。
7. 项目 A 转 `paused`，释放并发额度；恢复时只在需要时重建宿主。

## 5. 调度

### 5.1 事件驱动，不靠定时轮询

调度器是一个循环，只在三种情况下醒来：

| 唤醒源 | 例子 |
|---|---|
| **命令** | 确认规划、暂停、恢复、人工裁决、调序、人工验收 |
| **到期时间** | 重试退避到期、熔断到期、会话空闲超时 |
| **完成回报** | 一次尝试结束（成功/失败/取消） |

没有到期时间时它不做事，也不空转。另设一个 **30 秒兜底巡检**：只做对账与漏事件修正（孤儿会话、卡在中间态的任务），不承担业务推进。这样派发延迟从"最多 500ms"变成"即时"，也让顺序确定（命令串行处理）。

### 5.2 条件更新（compare-and-set）

派发前不改"先查再写"，而是一条带条件的 UPDATE：

```sql
UPDATE tasks SET status='executing', agent_id=?, attempt=attempt+1, version=version+1
WHERE id=? AND version=? AND status IN ('planned','ready');
```

影响 1 行 → 抢到，继续派发；影响 0 行 → 状态已被别人改过，放弃本次派发。它挡住三种情况：两次唤醒重叠、界面与调度同时操作、重启后旧回报晚到。

### 5.3 并发上限与暂停

- 并发分三层：全局（默认 8，可配 32）、工程、项目。多仓工程固定为 1（项目与任务都串行）。
- **软暂停**：停止新派发，等在途尝试自然结束。
- **强制暂停**：取消在途会话（§4.2）；取消粒度是会话，不是项目、不是进程。
- 人工裁决不受暂停影响。

## 6. 执行宿主与会话

### 6.1 两种接入方式

| 方式 | 形态 | 取消 | 适合 |
|---|---|---|---|
| **HTTP 宿主（实验，`DOMO_OC_HTTP=1`）** | **每个工作区**起一个 `opencode serve`（单仓 = 任务 worktree；多仓 = 工程目录，任务串行复用；同一工作区的重试/验收复用），DOMO 用 HTTP 创建会话、发消息、订阅事件、取消 | **会话级** | 编程可靠性优先：结构化事件、明确错误码、可中断、可查状态 |
| **独立进程（当前默认）** | 每次尝试 `opencode run --standalone`，一进程一会话 | 进程级（安全，因为只服务一个会话） | 宿主不可用、版本不匹配、或需要最大隔离 |

**为什么长期方向是 HTTP**：CLI 模式只能解析命令行输出，拿不到可靠的会话状态与取消通道，格式一变就要跟着改；HTTP 模式下"取消某个会话""查询会话状态""错误类型"都是接口语义，不需要猜文本。代价是与宿主 API 版本耦合、要管理宿主生命周期——用启动时版本探测 + 自动降级到 CLI 模式来兜。

`opencode run --server <url>` 属于中间形态：仍是 CLI 解析，但会话在受管宿主里。只在调试时使用，不作为生产路径。

### 6.2 宿主能力与准入

每个适配器必须声明：

| 能力 | 取值 | 用途 |
|---|---|---|
| 会话是否共享进程 | `per_run` / `shared` | 决定能否进程级取消 |
| 取消粒度 | `session` / `process` | 决定强制暂停怎么实现 |
| 协议版本 | 语义化版本 | 不兼容时拒载并降级 |
| 并发上限 | 数字 | 派生并发额度 |

**准入规则**：宿主与**工作区**一一绑定（隔离域 = 工作区），会话不跨工作区复用；同一工作区内的执行、验收、重试共用宿主。单仓因此天然一任务一宿主；多仓按产品要求串行，共用一个宿主，**切项目/切分支前必须停止宿主**。宿主数量设上限，超出时降级为 `opencode run --standalone`。

### 6.3 取消与终止

1. 优先会话级取消（HTTP `abort`）。
2. 无会话级取消且宿主仅服务当前项目 → 终止进程组：`setsid` 建组 → TERM 组 → 3s → KILL 组 → 确认组内退出。
3. 共享宿主且无会话级取消 → 禁止直接杀，交人选择（§4.2 第 5 步）。
4. 启动时扫描孤儿：按启动标记（环境变量 + 工作目录）识别 DOMO 起过的残留宿主与进程组，回收后重建。
5. 所有取消都留事件：谁取消、取消范围、是否影响其他项目。

### 6.4 输出与背压

- 会话事件流 → 有界队列 → 日志缓冲（每任务最近 5000 行）+ 批量落库（200ms 或 200 行）。
- 队列满时暂停读取（背压），不无限占内存；界面慢不拖累执行。

## 7. 数据

### 7.1 SQLite 的用法

- WAL 模式 + `busy_timeout` + 短事务。**WAL 本身保证写事务串行**，不需要额外的"写队列"组件。
- 一个写连接（天然串行）+ 若干读连接（只读）。写连接只用于状态、事件等短事务；任何长操作都不持有连接。
- 所有写操作毫秒级完成；日志走批量提交，减少事务与落盘次数。
- 迁移按 `user_version` 顺序执行、只增不改；启动时校验版本，版本过高拒绝启动，防止旧程序写坏新库。

### 7.2 一致性

- 状态迁移一律条件更新 + `version`。
- 状态、事件、收件箱条目在**同一事务**内提交；提交成功后才广播。
- 事件是唯一事实来源；界面状态是事件的投影，可重放重建。

### 7.3 事件与实时推送

- `events` 只追加；`id` 单调递增，同时作为 SSE 事件 id。
- 断线重连带 `Last-Event-ID`，服务端先回放缺失区间，再转入实时流。
- 同一实体在 120ms 内多次变化只推最后一次快照；广播丢失不影响正确性（可靠游标补齐）。
- 翻页用游标（`id < cursor`），不用大偏移。

### 7.4 日志与归档

- 日志按任务与轮次存储，内存留最近 5000 行供实时查看。
- 完整 agent 输出入库；超过 1MB 的正文落文件，库里只存指针与摘要。
- 在线保留期默认 90 天；超出导出为按月压缩文件，界面透明查询；归档只增不改。

### 7.5 备份与升级

- 启动 `quick_check`，失败则拒绝启动并提示恢复。
- 备份：启动前、迁移前、每 6 小时、每日；保留 7 份 + 每周 1 份。
- 升级：备份 → 事务内迁移 → 校验 → 启动；迁移失败回滚并保留旧库。

## 8. 可靠性

### 8.1 必须始终成立

1. 只有调度器改状态，且每次都走条件更新。
2. 事件先落库，后广播。
3. 外部副作用（起进程、跑 git）在状态提交之后发生；重复执行安全（尝试号 + 阶段作幂等键）。
4. 长操作不持有数据库连接。
5. 进程消失必须归账：不留"执行中"的幽灵任务。
6. 归档与事件不可修改。

### 8.2 故障处置

| 故障 | 检测 | 处置 |
|---|---|---|
| 一次尝试 panic/异常退出 | 完成回报缺失 / 进程守护 | 归账并回退状态，记录事件，不重复派发 |
| 会话卡死 | 最近输出时间超过阈值 | 取消会话 → 换下一优先级（不计失败预算） |
| 宿主崩溃 | 健康检查 / 连接失败 | 标记该宿主所有会话待恢复 → 重建宿主 → 按三档恢复 |
| 宿主被强制终止 | 取消流程 | 连带会话记 `interrupted_by`，进待恢复，收件箱提示 |
| 限流/额度不足 | 适配器错误分类 | 该 agent 全局熔断 → 改派 |
| 数据库忙 | 写超时 | 有限退避重试；仍失败则暂停派发并告警 |
| 磁盘将满 | 周期检查 | 停止派发、只读降级、收件箱告警 |
| 掉电 | 重启对账 | WAL 恢复 + 对账，最多丢最后一个未提交事务 |
| git 冲突 | 合入失败 | 中止合并、保留工作区、收件箱 |
| 界面断线 | SSE 断开 | 重连按游标回放，最终一致 |
| 调度器 panic | 进程守护 | 重启 + 对账 + 重建内存态 |
| 迁移失败 | 事务 + 版本校验 | 回滚到备份并拒绝启动 |

### 8.3 启动对账

打开库并校验 → 迁移 → 加载配置 → 对账（`executing` 但无存活会话 → 待恢复；合并重复收件箱条目；回收孤儿工作区与宿主；清理过期熔断）→ 启动调度器 → 接受请求。对账幂等，重复执行不产生副作用。

### 8.4 停机

停止接单 → 冻结派发 → 取消会话（限时）→ 落盘在途状态 → 数据库检查点 → 退出；超时未退出的进程组直接终止，任务转为待恢复。

## 9. 性能

| 热点 | 做法 |
|---|---|
| 状态写入 | 短事务 + 单写连接；一次尝试只写几次 |
| 日志 | 批量提交 + 内存环形缓冲 |
| 列表查询 | 覆盖索引 + 游标翻页；项目详情一次聚合查询，避免 N+1 |
| 大文本 | 正文落文件，库内只存指针 |
| 界面推送 | 同实体合并 + 120ms 节流；慢客户端丢中间帧 |
| 前端 | 按实体订阅、虚拟滚动、路由级分包 |

容量目标：默认 8 并行、可配 32；单库 100 万事件可翻页；单任务 10 万行日志；20 工程 / 200 项目；常驻内存 < 400MB。

## 10. 扩展

| 接口 | 作用 | 扩展方式 |
|---|---|---|
| Agent | 建会话、发消息、订阅输出、取消、能力声明 | 新增适配器（OpenCode HTTP / CLI、Mock、后续 A2A/MCP） |
| Workspace | 准备/清理任务工作区、越权检测、合入 | git / 普通目录 / 未来容器 |
| Verifier | 机械检查执行器 | 注册类型 + 参数结构 + 执行器 |
| Store | 持久化 | 目前只有 SQLite |
| Notifier | 通知渠道 | 应用内 / 桌面 / Webhook |
| SelectionStrategy | 选人与排队 | 优先级（默认）/ 轮转 / 负载 |

- **检查类型**自带参数结构，规划输出用同一结构校验；新增类型不动调度。首批：`file_exists`、`file_not_exists`、`command`。
- **协议版本**：接口响应带版本、事件带版本、迁移按版本递增；事件类型只增不删。
- **不做多用户**：若将来产品变化，需要重新设计鉴权、隔离与配额，不属于当前架构。

## 11. 可观测与安全

- 日志字段统一：工程、项目、任务、尝试、agent、阶段、结果；同时写文件与标准输出。
- 指标：派发数、成功率、平均时长、排队时长、数据库写耗时、SSE 连接数、熔断次数、宿主数、孤儿回收数。
- 诊断包：最近日志 + 指标快照 + 脱敏配置 + 事件尾部。
- 默认只监听 `127.0.0.1`；如开放局域网必须显式配置访问令牌。
- 命令在任务工作区内执行、无白名单但全程审计；有执行时限与输出上限。
- 凭据只从环境变量或本地配置读取，不入库、不入事件、不进归档。

## 12. 代码结构与当前映射

```
server/src/
  main.rs          # 装配与启停
  config.rs
  domain/          # 模型与状态机（无 IO）
  app/             # 调度、派发、规划/验收编排、恢复、合入、工作区、收件箱
  ports/           # 接口定义（Agent / Workspace / Verifier / Store / Notifier）
  adapters/
    sqlite/        # 迁移、仓储、事件、备份
    opencode/      # HTTP 宿主与会话；CLI 降级
    git/           # worktree、分支、合入、越权比对
    fs/            # 日志与归档
  api/             # 路由、传输对象、SSE
  obs/             # 日志、指标、诊断
```

| 现状 | 目标 |
|---|---|
| `db.rs` 单文件 + 全局锁 | `adapters/sqlite` + 单写连接/读池 |
| `scheduler.rs` 内直接 SQL 与直接起进程 | `app/*` + `ports/*`，状态只走一个出口 |
| `sandbox.rs` | `adapters/git` + `app/workspace_mgr`（术语改为任务工作区） |
| `agents/opencode.rs` | `adapters/opencode`：HTTP 宿主为一等公民，CLI 为降级 |
| `decision.rs` / `negotiation.rs` | 删除，不保留兼容层 |
| `api.rs` 单文件 | `api/` 按资源拆分 |

## 13. 实施阶段

| 阶段 | 内容 | 出口标准 |
|---|---|---|
| **A1 数据底座** | 单写连接/读池、条件更新 + version、游标翻页、备份、迁移版本化 | 修掉"持锁跑 git"冻结；`kill -9` 后库完整 |
| **A2 调度收敛** | 事件驱动 + 命令通道、30s 兜底巡检、进程守护、启动对账、优雅停机 | 重复唤醒/重启不重复派发；panic 自动恢复；24h 无泄漏 |
| **A3 宿主与会话** | HTTP 宿主（按工程隔离）、会话级取消、宿主能力与准入、进程组与孤儿回收、CLI 降级 | 强制暂停不影响其他工程；宿主崩溃可恢复；无残留进程 |
| **A4 实时与前端** | SSE 游标续传、合并节流、归一化缓存、虚拟列表、分包 | 断线重连自动补齐；10 万事件流畅 |
| **A5 扩展点** | 接口化、检查类型注册、选人策略、通知接口、协议版本 | 新增检查类型不改调度；新适配器只加目录 |

## 14. 关键决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | SQLite（WAL，单写多读） | 本地单用户，零运维；写入量远低于上限 |
| 2 | 调度器单写者 + 条件更新 | 消除重复派发与状态覆盖，状态可推理 |
| 3 | 事件驱动，30s 兜底巡检 | 派发即时、无空转；兜底只对账 |
| 4 | 事件只追加 + 快照投影 | 审计与恢复的刚需 |
| 5 | SSE + 事件游标 | 单向推送足够，断线可补齐 |
| 6 | 默认 HTTP 宿主，CLI 降级 | 会话级取消与结构化事件，编程可靠性高 |
| 7 | 隔离域 = 工作区 | 单仓每个 worktree 一个宿主；多仓共用一个宿主并在切分支前销毁；取消不跨工作区 |
| 8 | git worktree 隔离 | 同仓并行且合入语义清晰 |
| 9 | 多仓直接目录 + 串行 | 产品要求；不做并发与跨仓编排 |
| 10 | 单二进制托管前端 | 本地体验与部署成本优先 |
